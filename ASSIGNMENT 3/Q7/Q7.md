Aim
Design a concurrent system to process 10,000 student answer-script files, handle missing or corrupt files and generate a final result summary.

2. Pseudocode
START

Create a fixed thread pool

Create a ConcurrentHashMap
for storing student results

FOR each answer-script file

    Submit a Callable task

    Inside the task:

        TRY
            Read the file
            Validate student information
            Calculate marks
            Return student result

        CATCH file-related exceptions
            Return failure information

    Store the Future object

END FOR

FOR each Future

    Retrieve completed result

    Store successful results
    Count failed files

END FOR

Display:
    Total files processed
    Successful files
    Failed files

Shutdown ExecutorService

STOP
3. Java class design
Class

Responsibility

ResultProcessor

Controls the complete process

FileTask

Reads and validates files

Result

Stores student result

ConcurrentHashMap

Stores shared results safely

ExecutorService

Manages worker threads

4. Exception handling
FileNotFoundException – file is missing.

IOException – file reading failure.

NumberFormatException – invalid marks.

ExecutionException – task execution failure.

Each failed file is recorded without stopping the remaining tasks.

5. Expected output
Illustrative output for a test run with 10,000 files and 25 failures.

Semester Result Processing Started

Total Files: 10000
Successful Files: 9975
Failed Files: 25

Processing Completed Successfully.
Executor Service Shutdown.
6. Alternative concept
Approach

Description

ExecutorService

Uses a controlled thread pool

Parallel Streams

Processes files using parallel stream execution

One thread per file

Creates 10,000 separate threads

ExecutorService is preferred because it controls the number of active threads and reduces excessive thread creation.
